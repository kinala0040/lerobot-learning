**关键发现**：

```
文件结构:
  file-000.parquet: 0.64 MB (数值数据)
    - 25,650 行
    - 10 列
    - 列式压缩

性能测试:
  读取全部数据 (10 列): 0.1392 秒
  只读取 action 列 (1 列): 0.0255 秒
  
  加速比: 5.45x（快 5.45 倍！）
```

**列式存储的优势**：

| 操作 | 行式存储（CSV） | 列式存储（Parquet） |
|------|----------------|-------------------|
| 读取全部 | 1.0x | 1.0x |
| **只读 1 列** | 1.0x | **0.18x (快 5.5x)** |
| 文件大小 | 大 | **小（压缩）** |
| 内存占用 | 多 | **少** |

**为什么快？**
```
CSV（行式）：
  必须读取每一行的所有列，然后提取需要的列
  
Parquet（列式）：
  每列单独存储，直接读取需要的列，跳过其他列
```

#### 2. 视频解码机制 ✅

**成果**：
- 理解视频编码原理（关键帧 + 差分帧）
- 测试解码性能（顺序 vs 随机访问）
- 提取视频帧并保存为图像

**关键发现**：

**视频信息**：
```
编码格式: AV1 (libdav1d)
分辨率: 96×96
总帧数: 25,650
FPS: 10
时长: 2565 秒 (42.75 分钟)
文件大小: 6.57 MB

压缩率: 5 GB → 6.5 MB (800 倍！)
```

**性能测试结果** ⭐ **最重要的发现！**

```
顺序访问 100 帧:
  总耗时: 0.09 秒
  平均: 0.9 ms/帧  ✅ 快！

随机访问 10 帧:
  总耗时: 37.45 秒
  平均: 3745 ms/帧  ❌ 慢！

性能差异: 4150 倍！！！
```

**为什么差距这么大？**

```
视频结构：
  file-000.mp4 = Episode 0 + Episode 1 + ... + Episode 205
  (所有 206 个 Episode 拼接在一起！)

顺序访问（Episode 内）：
  帧 0 → 帧 1 → 帧 2 → ...
  利用差分帧 → 快

随机访问（跨 Episode）：
  帧 100 → 帧 15234 → 帧 420 → ...
  需要重新定位 → 慢
```

**训练的最佳实践**：

| 策略 | Episode 顺序 | Episode 内部 | 速度 |
|------|-------------|-------------|------|
| ❌ **帧级别随机** | 随机 | 随机 | 3745 ms/帧（极慢）|
| ✅ **Episode 级别随机** | 随机 | **顺序** | 0.9 ms/帧（快 4150x）|

**类比**：
```
帧级别随机 = 看书时每次随机翻一页
  → 翻来翻去，找不到页码，很慢 ❌

Episode 级别随机 = 随机选章节，但每章从头读到尾
  → 章节顺序乱，但每章顺序读，快很多 ✅
```

### 2. 性能关键点

#### Parquet 列式存储

```
读取 1 列 vs 读取全部:
  - 只读 1 列：快 5.5 倍
  - 内存占用：减少 57%
  
应用:
  训练时只读 observation.state 和 action
  → 比读取全部数据快 5 倍！
```

#### 视频顺序访问

```
顺序 vs 随机:
  - 顺序访问：0.9 ms/帧
  - 随机访问：3745 ms/帧
  - 差异：4150 倍！
  
应用:
  Episode 级别随机 + Episode 内顺序
  → 既有随机性，又快！
```

### 3. 训练最佳实践

```python
# ✅ 正确的训练循环
for epoch in range(100):
    # 1. 随机打乱 Episode 顺序
    episodes = list(range(206))
    random.shuffle(episodes)
    
    # 2. 按 Episode 处理
    for ep_idx in episodes:
        # 3. Episode 内顺序读取
        for frame in episode[ep_idx]:

优点:
  - Episode 之间：随机（满足训练需求）
  - Episode 内部：顺序（快 4150 倍）
```

### 常见面试问题准备

#### Q1: 如何保证数据质量？

**答**：
```
我采用四步法：

1. 探索阶段：
   - 统计关键指标的分布（方差、动作变化、数值范围）
   - 可视化异常值

2. 规则定义：
   - 基于 ISO/IEC 5259 国际标准
   - 数据驱动设置阈值（P1、P99 分位数）

3. 自动检测：
   - Episode 级别检查（保持数据连续性）
   - 生成详细报告（异常位置、原因、影响）

4. 人工验证：
   - 抽查被标记的 Episode
   - 迭代调整阈值
```

#### Q2: 为什么视频解码这么慢？

**答**：
```
视频压缩的原理是：关键帧 + 差分帧

顺序访问时：
  - 解码一个关键帧
  - 后续帧只需应用差分 → 快

随机访问时：
  - 需要找到最近的关键帧
  - 从关键帧逐帧解码到目标帧 → 慢

在我的测试中，随机访问比顺序访问慢 4150 倍。

所以训练时要用 Episode 级别随机，而不是帧级别随机。
```

#### Q3: 如何优化数据加载？

**答**：
```
我采用三个优化策略：

1. 列式存储（Parquet）：
   - 只读需要的列 → 快 5.5 倍
   
2. Episode 级别随机：
   - Episode 内顺序访问 → 快 4150 倍
   
3. 多进程并行：
   - num_workers=4 → 提高吞吐量
   - prefetch_factor=2 → 预加载下一个 batch

理论上，这三个优化可以让数据加载速度提升 20,000 倍以上。
```
