## 一、为什么需要数据质量检查？

### 1.1 机器人数据的特点

**数据量少，质量要求高**：
- 网络路由 RL：百万级数据，坏样本影响小
- 具身智能：只有 206 个 Episode，每个坏样本都会显著影响训练

**数据收集成本高**：
- 需要人类演示或真实机器人
- pusht：206 episodes ≈ 40 分钟人类操作时间
- 真实机器人：可能需要数小时到数天

**训练方式敏感**：
- 模仿学习直接拟合人类动作
- 坏的演示 → 模型学到错误行为
- 无法通过"更多数据"来稀释坏样本（数据太少）

---

### 1.2 数据质量问题的影响

| 质量问题 | 表现 | 训练影响 |
|---------|------|---------|
| **时间戳不连续** | 0.0, 0.1, 0.3, 0.4（缺 0.2） | 动作预测错误，模型学到错误的"速度" |
| **缺失字段/NaN** | state = [NaN, 97.0] | 梯度爆炸，训练无法收敛 |
| **Episode 过短** | 只有 5 帧 | 无法学到完整任务轨迹 |
| **动作突变** | action 从 [100, 100] 跳到 [400, 50] | 模型学到"瞬移"，实际执行时失败 |
| **图像损坏** | 全黑或全白图像 | CNN 无法提取有效特征 |
| **数据泄漏** | train 和 test 有相同 Episode | 评估结果虚高，泛化能力差 |

#### ⚠️ 任务成功率

```
成功 Episode: 0/206
成功率: 0.0%
```

**这不是问题！原因**：

1. **数据标注问题**：
   - `next.success` 字段可能未正确设置
   - 数据收集时没有记录成功标志

2. **不影响模仿学习**：
   - Behavior Cloning 只需要人类动作（作为监督学习的标签）
   - 不需要 reward 或 success 信号
   - 训练目标：`loss = ||policy(observation) - human_action||²`

3. **何时需要关注成功率**：
   - ✅ 如果用 RL（需要 reward）
   - ✅ 如果做数据过滤（只保留成功的 Episode）
   - ❌ 模仿学习不需要

---

#### ✅ 时间戳连续性

```
✅ 时间戳检查通过：所有时间戳连续且均匀
时间戳异常: 0 个
```

**检查逻辑**：
- 期望帧间隔：`dt = 1 / FPS = 1 / 10 = 0.1 秒`
- 检查每对相邻帧：`|actual_dt - 0.1| < 0.005`（允许 5% 误差）

**为什么重要**：
- 时间戳不连续 → 动作速度计算错误
- 示例：
  ```
  Frame 0: t=0.0, position=(100, 100)
  Frame 1: t=0.1, position=(110, 105)  ← 速度 = (10, 5) / 0.1 = (100, 50) px/s
  
  如果时间戳错误：
  Frame 1: t=0.2, position=(110, 105)  ← 速度 = (10, 5) / 0.2 = (50, 25) px/s
  → 模型学到错误的速度
  ```

**为什么重要**：

#### ✅ 数值范围

```
图像 (observation.image):
   范围: [0.094, 1.000]
   期望: [0.0, 1.0] (归一化)
   ✅ 在合理范围内

状态 (observation.state):
   X 范围: [30.2, 447.2]
   Y 范围: [64.1, 479.2]

动作 (action):
   X 范围: [32.0, 450.0]
   Y 范围: [71.0, 470.0]
```

**理解状态和动作的范围**：
- **不是** 图像像素坐标 [0-96]
- **是** 更大的物理空间坐标 [30-450]
- 图像只是这个物理空间的"观测视图"

**类比**：
```
物理世界：500×500 的工作空间
       ↓ 渲染
观测图像：96×96 像素
```

**为什么重要**：
- 如果图像范围 [-100, 300] → 归一化错误
- 如果动作范围 [0, 1e10] → 可能有异常值

**好的分布**：

**坏的分布**：
- ❌ 只在一个小角落（数据多样性低）

**横轴**：Action X

**观察要点**：

**好的分布**：

### 6.1 可以回答的问题

**Q1: 你如何检查机器人数据的质量？**

> "我设计了一个全面的数据质量检查流程，包含 5 个维度：
> 
> 1. **Episode 统计**：长度分布、成功率，确保数据集规模和任务一致性
> 2. **时间戳连续性**：检查帧间隔是否均匀（FPS=10，dt=0.1s），防止跳帧导致的速度计算错误
> 3. **数据完整性**：检查缺失字段和 NaN 值，避免训练崩溃
> 4. **数值范围**：确认图像归一化、状态和动作在合理范围内
> 5. **可视化分析**：生成长度分布、状态空间、动作空间的图表
> 
> 我将结果保存为 JSON 报告和可视化图表，方便版本控制和对比实验。"

---

**Q2: pusht 数据集的成功率是 0%，这是问题吗？**

> "这不是问题。pusht 使用模仿学习（Behavior Cloning），训练目标是最小化预测动作和人类动作的 MSE 损失，不需要 reward 或 success 信号。
> 
> 0% 成功率可能是因为：
> 1. 数据标注问题（success 字段未设置）
> 2. 数据集包含探索过程（不只是成功案例）
> 
> 只有在用 RL 训练或需要过滤失败案例时，才需要关注成功率。对于监督学习，只要人类演示质量高，就能训练出好模型。"

---

**Q3: 时间戳连续性为什么重要？**

> "时间戳不连续会导致模型学到错误的动作速度。
> 
> 举例：如果机器人从位置 (100, 100) 移动到 (110, 105)，实际耗时 0.1 秒，速度是 (10, 5) / 0.1 = (100, 50) 像素/秒。但如果时间戳错误记录为 0.2 秒，模型会学到速度是 (50, 25) 像素/秒，部署时会执行得太慢。
> 
> 我检查了所有相邻帧的时间间隔，确认都符合 FPS=10 的预期（dt=0.1s，允许 5% 误差），没有跳帧。"

---

**Q4: 你如何判断 Episode 长度分布是否合理？**

> "我主要看三个指标：
> 
> 1. **平均值和中位数接近**：pusht 是 124.5 vs 122，说明分布对称，没有极端值拉偏
> 2. **标准差适中**：35.59 帧，约为平均值的 28%，说明长度变化在合理范围内
> 3. **最短和最长合理**：49-246 帧（5-25 秒），没有 1 帧的损坏数据或 10000 帧的异常
> 
> 可视化显示钟形分布，说明任务难度一致。如果是双峰分布，可能混合了两种任务类型，需要分别处理。"
